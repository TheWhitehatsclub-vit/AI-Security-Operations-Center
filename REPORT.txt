================================================================================
  1. PROJECT OVERVIEW
================================================================================

  NeuralOps is a full-stack AI-powered Security Operations Center (SOC) that
  collects logs and network traffic from a target application, detects attacks
  using a rule-based engine + ML anomaly detection + threat intelligence, and
  uses confidence scoring to produce actionable alerts — all pushed to Redis
  for a real-time dashboard.

  Core philosophy:
    A rule engine filters 10,000 logs/hour down to ~10 suspicious ones.
    Only those suspicious logs are sent for deep analysis (fast, cost-efficient).
    Rules catch it fast — AI explains it smart.

  What NeuralOps covers:
    - SIEM — Security Information and Event Management (log collection + correlation)
    - SOC — Security Operations Center workflow (alert triage, assign, escalate, close)
    - AI — Gemini API for threat explanation and IR playbook generation
    - Automation — real-time detection without manual log reading
    - Web Development — full-stack React + FastAPI dashboard

================================================================================
  2. SYSTEM ARCHITECTURE — 5 LAYERS
================================================================================

  Layer 1: Data Ingestion
    Log sources: FastAPI middleware, nginx access.log, system auth logs (journald),
                 network packets (scapy)
    Normalises everything into a JSON envelope and queues it in Redis Streams.

  Layer 2: Detection Engine
    3 parallel workers consuming from Redis:
      (1) Rule engine — regex/threshold patterns for 63 attack signatures
      (2) ML anomaly detector — Isolation Forest flags statistical outliers
      (3) Threat intel — AbuseIPDB + VirusTotal + GreyNoise API lookup

  Layer 3: AI Analysis (Gemini — optional)
    Only suspicious logs reach this layer. Gemini Flash explains each alert
    in plain English. Gemini Pro generates an IR playbook using MITRE ATT&CK context.

  Layer 4: Backend API
    REST endpoints for alert CRUD, WebSocket for real-time push to dashboard,
    PostgreSQL for incident storage, Elasticsearch for full log search.

  Layer 5: Frontend Dashboard
    Real-time alert feed with severity colour coding, threat detail view with
    AI explanation, IR playbook panel, SIEM log explorer with search/filter.

  Data flow:
    Logs -> Redis Streams -> Rule Engine -> Alert Queue -> Scorer -> Redis Alerts -> Dashboard

  5. DATA FLOW — END TO END
================================================================================

  STEP 1: RAW LOG ENTERS REDIS STREAM
  ──────────────────────────────────────────────────────────────────────
  An attacker sends a malicious HTTP request:
    GET /login?user=admin&pass=1'+OR+'1'='1'-- HTTP/1.1
    User-Agent: sqlmap/1.7

  The FastAPI middleware collector captures this and pushes to Redis:
    neuralops:logs <- {
      "source_ip": "203.0.113.42",
      "method": "GET",
      "url": "/login?user=admin&pass=1'+OR+'1'='1'--",
      "status": "200",
      "user_agent": "sqlmap/1.7"
    }

  STEP 2: PARSER LAYER — NORMALIZE + DECODE
  ──────────────────────────────────────────────────────────────────────
  The rule engine worker reads from Redis and normalizes the log:
    - Flattens nested fields
    - URL-decodes: %27 -> ', %3D -> =, %2F -> /
    - Double-decodes: %252e -> %2e -> .
    - HTML-entity decodes: &lt; -> <
    - Extracts base64 payloads: atob('YWRtaW4=') -> "admin"
    - Extracts URL query parameters

  STEP 3: ENRICHMENT LAYER — GEOIP LOOKUP
  ──────────────────────────────────────────────────────────────────────
  The IP 203.0.113.42 is looked up in MaxMind GeoLite2:
    geo: {
      "country": "RU",
      "city": "Moscow",
      "asn": "12345",
      "isp": "Some ISP"
    }

  If GeoIP DB is not loaded, enrichment is skipped — engine still works.

  STEP 4: BEHAVIORAL BASELINE
  ──────────────────────────────────────────────────────────────────────
  The IP is added to the behavioral profiler:
    - Tracks total requests, methods used, paths visited, status codes
    - Records user-agents, body sizes, request timing
    - On subsequent requests, flags anomalies:
      * Unusual HTTP method (e.g., DELETE when only GET seen)
      * Unusual user-agent
      * Request rate spike (3x normal)
      * Body size 10x normal

  STEP 5: DETECTION ENGINE — 63 RULES SCANNED
  ──────────────────────────────────────────────────────────────────────
  Each rule type is checked:

  REGEX RULES (most common):
    SQL Injection rule fires:
      Pattern: r"'\s*OR\s*'1'\s*=\s*'1"
      Matches: "'+OR+'1'=" in the URL
      Base score: 90/100 -> raw score = min(1.0, 9/50) * 0.9 = 0.162

  THRESHOLD RULES (brute force, DDoS):
    Brute Force: counts 401s per IP per 60s window
    SYN Flood: counts SYN flags per IP per 10s window

  THRESHOLD_UNIQUE RULES (dir busting, port scan):
    Dir Busting: counts unique 404 paths per IP per 60s window

  TIME-BASED RULES (off-hours access):
    Flags sensitive path access between 12AM-5AM and 10PM-11PM

  CORRELATION RULES (error spikes):
    Counts 5xx errors per IP per 10s window

  GEOIP RULES:
    Login from suspicious country: boosts score if country in [RU, CN, IR, KP, ...]

  STEP 6: CONFIDENCE SCORING
  ──────────────────────────────────────────────────────────────────────
  The scorer fuses multiple signals into one final confidence (0.0-1.0):

    Rule score:        0.162  (from pattern match)
    Behavioral anomaly: +0.0   (first request from this IP)
    Attack chain:       +0.0   (no prior events from this IP)
    Obfuscation:        +0.0   (no encoding detected)
    Base64 payload:     +0.0   (not present)
    ─────────────────────────────────────────────────
    FINAL CONFIDENCE:   0.162
    SEVERITY:           LOW (0.15-0.35)
    TTP:                T1190 (Exploit Public-Facing Application)
    KILL CHAIN:         Exploitation

  STEP 7: DEDUP + FEEDBACK CHECK
  ──────────────────────────────────────────────────────────────────────
    - Fingerprint: md5("SQL Injection|203.0.113.42|'+OR+'1'=")
    - Checked against dedup cache (300s TTL). If seen recently, suppressed.
    - Checked against FP registry. If marked false positive, suppressed.

  STEP 8: ALERT GROUPING INTO INCIDENTS
  ──────────────────────────────────────────────────────────────────────
    - Same rule_name + same source_ip within 60s are grouped
    - If 10+ alerts accumulate, flushed as one incident
    - After 60s of inactivity, group is flushed regardless

    Single alert -> emitted directly to neuralops:alerts
    Grouped      -> emitted to neuralops:incidents with all alert_ids

  STEP 9: FINAL ALERT EMITTED
  ──────────────────────────────────────────────────────────────────────
    neuralops:alerts <- {
      "id": "abc-123-def",
      "timestamp": "2026-06-22T21:53:06Z",
      "rule_name": "SQL Injection",
      "category": "web",
      "severity": "LOW",
      "confidence": 0.162,
      "ttp": "T1190",
      "kill_chain": "Exploitation",
      "source_ip": "203.0.113.42",
      "matched_value": "'+OR+'1'=",
      "geo": { "country": "RU", "city": "Moscow", "asn": "12345" },
      "description": "SQL Injection detected",
      "incident_id": ""
    }

  STEP 10: OUTPUT ADAPTERS
  ──────────────────────────────────────────────────────────────────────
    - Written to /tmp/neuralops_alerts.log (JSON lines)
    - Optional: Sent to Slack webhook
    - UI team reads neuralops:alerts from Redis for the dashboard

================================================================================
  7. RULE HOT-RELOAD
================================================================================

  Rules can be updated at runtime without restarting any worker.

  How it works:
    1. Worker starts with static rules from engine/rules.py
    2. Background task checks Redis every 30 seconds
    3. If redis key "neuralops:rules_config" exists with hash field "rules",
       it parses the JSON and replaces all rules
    4. Falls back to static rules if Redis key is deleted

  Usage:
    # Deploy new rules at runtime:
    redis-cli HSET neuralops:rules_config rules "$(cat my_rules.json)"

    # Revert to static rules:
    redis-cli DEL neuralops:rules_config

  This allows the SOC team to tune rules without DevOps involvement.

  8. GEOIP ENRICHMENT
================================================================================

  Every incoming IP is looked up against MaxMind GeoLite2 databases:

  Fields added to every alert:
    geo.country    - ISO country code (e.g., "RU", "US", "CN")
    geo.city       - City name (e.g., "Moscow", "Beijing")
    geo.asn        - ASN number (e.g., "12345")
    geo.isp        - ISP name (e.g., "Rostelecom")
    geo.is_private - True for 10.x, 172.x, 192.168.x, 127.x

  GeoIP-powered rules (3):
    - Login from unexpected country
    - Admin access from high-risk country [RU, CN, IR, KP, SY, CU, VE, NG, PK]
    - Sensitive endpoint from unknown country

  Setup:
    python3 scripts/download_geoip.py

  Graceful degradation: No database = no enrichment = engine still works.

================================================================================
  9. LOG COLLECTION METHODS (4)
================================================================================

  Method 1: FastAPI Middleware (easiest — 20 lines of code)
    Attach to any FastAPI app. Every HTTP request is automatically logged
    and pushed to Redis. Captures: IP, method, path, query, body, status,
    user-agent, latency.

  Method 2: File Tail
    Reads /var/log/nginx/access.log and /var/log/auth.log in real-time
    using a tail loop. Parses common log format. No agents needed.

  Method 3: Network Packet Capture (scapy)
    Sniffs eth0 interface. Detects port scans, SYN floods, ARP poisoning —
    attacks that never appear in application logs.

  Method 4: Systemd Journal
    Reads SSH, sudo, and auth events from Linux system journal.
    Catches brute force SSH, privilege escalation, new user creation.

  11. WORKERS — WHAT EACH DOES
================================================================================

  Worker            Source File           Function
  ──────────────────────────────────────────────────────────────────────
  Rule Engine       workers/rule_engine.py  Main orchestrator. Reads logs
                                            from Redis, normalizes, enriches,
                                            matches rules, scores, dedups,
                                            groups, emits alerts.

  ML Anomaly        workers/ml_anomaly.py   Isolation Forest on 10 features
                                            (body length, URL length, status,
                                            latency, method, UA length).
                                            Retrains every 120s on 1000-sample
                                            sliding window.

  Threat Intel      workers/threat_intel.py  Async lookup of IPs via
                                             AbuseIPDB, GreyNoise, and
                                             file hashes via VirusTotal.
                                             5min cache to avoid rate limits.

  Output            workers/output.py       Reads neuralops:alerts and
                                            writes to /tmp/neuralops_alerts.log
                                            + optional Slack webhook.

  12. DEPLOYMENT
================================================================================

  Quick start (local):
    # 1. Start Redis
    redis-server --daemonize yes

    # 2. Install dependencies
    pip install -r requirements.txt

    # 3. Download GeoIP databases (optional)
    python3 scripts/download_geoip.py

    # 4. Start collectors (as root for scapy + auth.log)
    sudo python3 -c "from collectors.filetail import FileTailCollector; import asyncio; asyncio.run(FileTailCollector().run())" &
    sudo python3 -c "from collectors.scapy import ScapyCollector; import asyncio; asyncio.run(ScapyCollector().run())" &

    # 5. Start detection engine
    python3 workers/rule_engine.py &
    python3 workers/ml_anomaly.py &
    python3 workers/threat_intel.py &
    python3 workers/output.py &

    # 6. Seed test attacks to verify
    python3 scripts/seed_test_attacks.py

    # 7. View alerts
    redis-cli XLEN neuralops:alerts
    redis-cli XREAD COUNT 5 STREAMS neuralops:alerts 0

  Docker:
    docker-compose up -d

  Environment variables:
    REDIS_URL          (default: redis://localhost:6379/0)
    ABUSEIPDB_KEY      (optional, for threat intel)
    VIRUSTOTAL_KEY     (optional, for threat intel)
    GREYNOISE_KEY      (optional, for threat intel)
